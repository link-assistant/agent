# Solution plans

For each defect in [`root-causes.md`](root-causes.md): the options considered and the reason for the choice.

| Defect                 | Options considered                                                                                                           | Chosen                                    | Why                                                                                                                                                                                                                        |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1 SECONDS early kill  | (a) raise the test's budget; (b) retry the flaky test; (c) `-gt` deadline; (d) measure with `date +%s%N`                     | (c), plus the template's hardened wrapper | (a) and (b) hide the bug the test found. (d) is not portable: macOS `date` has no `%N`. `-gt` is a one-character fix that proves a full budget passed, and it costs at most one extra second.                              |
| D2 Rust warnings       | (a) `cargo clippy -- -D warnings` only; (b) workflow-wide `RUSTFLAGS=-Dwarnings` + `RUSTDOCFLAGS` + manifest check           | (b)                                       | It matches the Rust template, and it also covers rustc warnings in build and test jobs, rustdoc, and Cargo manifest warnings.                                                                                              |
| D3 changeset counting  | (a) delete stale changesets by hand; (b) count only the files the PR adds                                                    | (b)                                       | (a) treats the symptom. The next failed release would recreate it.                                                                                                                                                         |
| D5/D6 install warnings | (a) `--engine-strict=false`/ignore; (b) Node 26 and a refreshed pin + `strict-allow-scripts`                                 | (b)                                       | Warnings that change nothing are noise. A stale pin silently skipped `node-pty`'s install script.                                                                                                                          |
| D7 AI SDK              | (a) silence `AI_SDK_LOG_WARNINGS`; (b) migrate to `generateText` + `Output.object` and capture warnings                      | (b)                                       | It removes the deprecation and makes the warning tests able to fail.                                                                                                                                                       |
| D8 crates.io error     | (a) `continue-on-error`; (b) gate the OIDC step on a repository variable                                                     | (b)                                       | `continue-on-error` still prints `##[error]`. A variable states intent and needs no workflow edit when trusted publishing is configured.                                                                                   |
| D10 instant release    | (a) a separate quality workflow; (b) `needs` + `success` checks                                                              | (b)                                       | It is the same pattern as the automated release. A policy test keeps every release job gated.                                                                                                                              |
| D11 rerun detection    | (a) query npm for the version; (b) `GITHUB_RUN_ATTEMPT`                                                                      | (b)                                       | It is exact for instant mode, needs no network, and keeps changeset mode unchanged.                                                                                                                                        |
| D12 gate               | (a) always fail on cancellation; (b) never fail off main (old); (c) fail unless superseded _and_ the job cancels in progress | (c)                                       | (a) turns every superseded PR run red. (b) hides timeouts. (c) is the template's design, with two improvements: the `github.ref` expressions are evaluated, and `refs/pull/<n>/head` makes the head lookup work for forks. |
| D13 Rust release state | (a) patch the shell `if` chain; (b) a pure decision function + CLI                                                           | (b)                                       | It is unit-testable, and "unknown" becomes an explicit failure.                                                                                                                                                            |
| D14/D15 push races     | (a) a `concurrency` group on release; (b) rebase-and-retry push, tag after push                                              | (b)                                       | Releases already share a concurrency group. The race is with ordinary merges, which no group covers.                                                                                                                       |
| D16 model keys         | (a) skip Groq without a key; (b) fail with the secret's name                                                                 | (b)                                       | The workflow is run by hand to test a model. A skip would report a test that never ran as success.                                                                                                                         |
